# kaggle 0.8.0 - A Split Playbook and the Hourly Status Block <!-- omit in toc -->

- [Moved Paths](#moved-paths)
- [Pre-flight](#pre-flight)
- [Migrate](#migrate)

For packs updating from 0.7.x. The playbook splits into a core that agents read at every session start
(`how-to-kaggle.skill.md`), four kind skills read once the competition's kind is known (`kaggle-kind-simulation`,
`kaggle-kind-tabular`, `kaggle-kind-llm-agents`, `kaggle-kind-ranking`) and `kaggle-kernels.skill.md`, read before
building a submission. Lease upkeep moved to the booking plugin, cloud-instance practice to the cloud-GPU plugin and
shared-host practice to `resource-sharing`. The hourly pass ends with a STATUS block and gains flags (board jumps,
unpushed commits, models outside the allowed list, failed hooks, spend limits, one line on HTTP 429), and the rule
says what to read when and that workers inherit the master's effort, the owner's choice per session.

## Moved Paths

None in the project: no project file or log moves. Inside the plugin copy, the playbook's Kernel Engineering
section moved to `<pack>/plugins/kaggle/kaggle-kernels.skill.md`, and its kind-specific notes to the
`kaggle-kind-*.skill.md` files.

## Pre-flight

- The project has this plugin copied at `<pack>/plugins/kaggle/` (`<pack>` is the project's ai-pack folder: default
  `aipack/`, `ai/` in older projects, any name). A linked project runs the live source: it skips step 1 and does the
  rest.
- List what the project's own files say about the playbook's sections: `grep -rn "how-to-kaggle\|Kernel
  Engineering\|playbook" <pack>/instructions.md <pack>/*.agent.md <pack>/.memory/directions.md tools/`.

## Migrate

1. Update the copy (`install-plugin` update): every `shared/` file of 0.8.0 into `<pack>/plugins/kaggle/`, including
   the new `kaggle-kernels.skill.md` and the four `kaggle-kind-*.skill.md` files. Fold any project-side edit to a
   plugin file into the plugin first (`import-plugin`).
2. Read the new core (`how-to-kaggle.skill.md`) in full, then record the competition's kind in the facts sheet
   (simulation and bot ladders, tabular, agent and LLM scorers, retrieval and ranking, or none of these) and read its
   kind skill. Read `kaggle-kernels.skill.md` before the next submission build.
3. Point the project's own lines that cited a moved part at its new home (the pre-flight grep): kernel engineering
   at `kaggle-kernels`, lease upkeep at the booking plugin's skill, cloud instances at the cloud-GPU plugin's run
   skill, shared hosts at `resource-sharing`.
4. Optional settings in `<pack>/.memory/config.json`, read by the hourly pass: `"kaggle.allowed_models"` (a list of
   model names, `*` allowed; default: Opus 5.5, Sonnet 5.5 and Haiku), `"brev.daily_limit_usd"` (the owner's daily
   Brev limit, when the project has one) and `"kaggle.master_effort"` (only when the owner asks for a fixed level;
   unset, no effort is judged). `"ai.daily_budget_usd"` works as before.
5. Optionally add a short `pick` text (today's pick) to `reports/status.json`; the STATUS block shows it.
6. Paste the hourly pass's STATUS block into the status message, and act on its new flags.
7. Record `{"name": "kaggle", "version": "0.8.0"}` in `<pack>/manifest.json` and re-baseline the `revisions` entries
   for `<pack>/plugins/kaggle/` (`revs baseline`).

## Validate

- `<pack>/plugins/kaggle/` holds `kaggle-kernels.skill.md` and the four `kaggle-kind-*.skill.md` files, and the
  facts sheet names the competition's kind.
- `python3 <pack>/plugins/kaggle/tools/kaggle_hourly.py <slug>` ends with a STATUS block and prints `git`, `agents`
  and `spend` lines.
- Nothing in the project's own files points at the playbook's old Kernel Engineering text or at lease upkeep in the
  playbook.

## Revert

- Restore the 0.7.x copy and the manifest entry `{"name": "kaggle", "version": "0.7.0"}` from the plugin's git
  history. The settings added in step 4 are ignored by 0.7.0 and can stay.
