For packs updating from 0.9.x. A pack still on 0.9.0 gets 0.9.1 here too: that release shortened the playbook core
without dropping a rule and shipped no migration, so the copy in step 1 brings it with no step of its own. Nothing
is breaking: every new status field and setting is optional, and the plugin works without the files the framework
and resource-sharing now write. What a project may need to change is its own scripts and habits around the hourly
pass and the gated submit:

- The hourly pass holds back a flag whose text has not changed (at most one full print every 6 hours): its line says
  `(unchanged)` instead of `FLAG`, a pass with only held flags prints `FLAGS: none new` and exits 0, and exit 10
  now means a flag printed in full. New lines and flags: `alerts`, `peers`, `plugins`, `own-line`, `settings`; new
  STATUS rows `outlook`, `progress` and `tracks`, and each machine's health in `compute`.
- `kaggle_submit.py --go` records a submit Kaggle refuses with HTTP 400, 401, 403, 404 or 429 (one pending entry, say) as `refused`, exit 5,
  with Kaggle's reason; a later `--go` needs no `--checked`.
- The status page shows the status JSON's optional `outlook`, `lineage` and `tracks`, a Machine Health table, and
  rolls up old finished plan items.

## Moved Paths

None: no project file or log moves. The hourly pass's state file (`__data/kaggle/<slug>/hourly/last.json`) gains
keys and reads an older one as it is. The plugin now reads, when present, `<pack>/.memory/clock.json` and
`<pack>/.memory/alerts.jsonl` (written by Solaris 0.45.0's session clock and hooks) and
`<pack>/.memory/host-health.json` (written by resource-sharing 0.4.0's `hosthealth.py --write`), its own and those
of the projects it shares machines with.

## Pre-flight

- The project has this plugin copied at `<pack>/plugins/kaggle/` (`<pack>` is the project's ai-pack folder: default
  `aipack/`, `ai/` in older projects, any name). A linked project runs the live source: it skips step 1 and does the
  rest.
- List the project's own scripts and notes that read the hourly pass or watch submissions: `grep -rln
  "kaggle_hourly\|kaggle_submit\|FLAG\|Client Error" tools/ source/ <pack>/instructions.md <pack>/.memory/schedule.json`
  (skip what does not exist).
- The Solaris checkout above the project: with 0.45.0 or newer, steps 5 and 6 apply in full; on an older one the
  `alerts` line prints nothing and `peers` flags nothing (no `clock.json` yet), and the card waits for the update.

## Migrate

1. Update the copy (`install-plugin` update): every `shared/` file of 0.10.0 into `<pack>/plugins/kaggle/`. Fold any
   project-side edit to a plugin file into the plugin first (`import-plugin`).
2. **Held flags.** Make each script that greps `FLAG` in the hourly output or acts on exit 10 treat `(unchanged)`
   lines and `FLAGS: none new` as nothing new, or have it read `--json` (`flags` counts the flags printed in full,
   `unchanged` names the held checks, each marked `"unchanged": true` in `checks`). A script that matched the stale
   page's text: it now reads "the page is over 2 hours old". To print every flag every pass as before, set
   `"kaggle.flag_repeat_hours": 0` in `<pack>/.memory/config.json`.
3. **Status fields.** Add to `reports/status.json` and keep current (the `kaggle-checks` skill, The status page):
   `"outlook"` (`{"at": "<ISO>", "lines": [{"when", "score", "rank", "basis"}]}`, at least daily and after each new
   best), `"lineage"` (the new bests oldest first, each `{"entry", "score", "gain", "origin": "own" | "public",
   "what", "date"}`; give each a `date`, or the own-line stall clock starts at the first pass that sees the entry)
   and `"tracks"` (one `{"name", "state", "last_gain", "note"}` per work track). Close finished plan items (done,
   dropped, superseded) so they roll up; set `"kaggle.status_plan_days"` when 3 days of full plan is not right. Then
   rebuild with `kaggle_status.py`.
4. **Refused submits.** Retire hand-made per-slot watch scripts that retry a submit or parse "400 Client Error" to
   tell a refusal: `kaggle_submit.py --go` now exits 5 and prints `REFUSED BY KAGGLE: <reason>`. Retry a refused
   entry at every hourly and last-call check until the reset, and report each refusal (the playbook core, Daily
   Submission Discipline, OD46). Scripts that treat exit 4 as the only failed submit also handle 5.
5. **Session clock** (Solaris 0.45.0 or newer): in `<pack>/instructions.md`, the Session clock line starts the clock
   with `--cap 55` in a Claude Code interactive session and arms it before every turn end, as the type's overlay
   now says (`plugins/kaggle/project-types/competition/{{PACK}}/instructions.append.md` in the Solaris checkout).
6. **Hard-rules card** (Solaris 0.45.0 or newer, which seeds `<pack>/card.md`): fill the card with the project's
   hard rules, at most about 3 KB, one line each; the list in `plugins/kaggle/competition.project.md`, Step 11, is
   a starting point. Add the overlay's Hard-rules card line to `<pack>/instructions.md` beside the Session clock
   line.
7. **Machine health.** With resource-sharing attached, update it to 0.4.0 too: the owner of each machine adds
   `--write` to its hourly `hosthealth.py --fix`, and the STATUS `compute` row and the page's Machine Health table
   read that file (resource-sharing's `migrations/0.4.0.md`).
8. Optional settings in `<pack>/.memory/config.json`: `"kaggle.flag_repeat_hours"` (default 6),
   `"kaggle.peer_silent_minutes"` (90), `"kaggle.own_stall_days"` (3) and `"kaggle.status_plan_days"` (3). A value
   that is not a number is a `settings` flag, and its default is used.
9. Run one hourly pass and settle what it flags: `plugins` names any other attached plugin older than the
   checkout's (the owner updates it at the Solaris root); `peers` names a peer's master that looks stopped (tell the
   owner, never that master).
10. Record `{"name": "kaggle", "version": "0.10.0"}` in `<pack>/manifest.json` and re-baseline the `revisions`
    entries for `<pack>/plugins/kaggle/` (`revs baseline`).

## Validate

- `python3 <pack>/plugins/kaggle/tools/kaggle_hourly.py <slug>` prints the STATUS rows `outlook`, `progress` and
  `tracks` (filled once the status JSON has the fields) and, in a project under a Solaris checkout, a `plugins`
  line; a second pass soon after shows unchanged flags as `(unchanged)`.
- `python3 <pack>/plugins/kaggle/tools/kaggle.py --sdk submissions <slug>` lists the latest submissions, with an
  `error:` line under each one Kaggle errored.
- The rebuilt status page shows Outlook, Work Tracks and Best-Score Lineage under Current State.
- The pre-flight grep finds no script that keys on `FLAG` or exit 10 without handling held flags, and none that
  parses "400 Client Error".

## Revert

- Restore the 0.9.x copy and the manifest entry `{"name": "kaggle", "version": "0.9.1"}` (or `0.9.0`) from the
  plugin's git history. The status fields and settings added here are ignored by 0.9.x and can stay. A record whose
  last attempt is `refused` needs `--checked` under 0.9.x, which treats it like an unclear attempt: read
  `competitions submissions` first, as for any unclear one.
