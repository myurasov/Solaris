# kaggle 0.7.0 - One Status Page Replaces the Live Plan <!-- omit in toc -->

- [Pre-flight](#pre-flight)
- [Migrate](#migrate)
- [Validate](#validate)
- [Revert](#revert)

For packs updating from 0.6.x. One status page per project, `reports/status.pdf`, built by `tools/kaggle_status.py`
from the hand-edited `reports/status.json`, replaces every live PDF: the live plan and the phase progress reports.
`tools/kaggle_live_plan.py` is now a stub that exits 2, and the hourly pass checks the status page.

## Pre-flight

- The project has this plugin copied at `<pack>/plugins/kaggle/` (`<pack>` is the project's ai-pack folder: default
  `aipack/`, `ai/` in older projects, any name). A linked project runs the live source: it skips step 1 and does the
  rest. An ad-hoc task without a live plan needs nothing here.
- List what builds the live plan or a phase progress report: the pack's instructions, worker briefs, scripts and the
  schedule (the plan's `clock` file, `<pack>/.memory/schedule.json`). Each of them changes below.

## Migrate

1. Update the copy (`install-plugin` update): every `shared/` file of 0.7.0 into `<pack>/plugins/kaggle/`, including
   the new `tools/kaggle_status.py`. Fold any project-side edit to a plugin file into the plugin first
   (`import-plugin`).
2. Write `reports/status.json` from `submissions/live-plan.json` (keys and an example: the docstring of
   `tools/kaggle_status.py`). Copy the shared keys as they are: `rev`, `competition`, `team`, `timezone`, `tz_label`,
   `render_env`, `clock`, `daily_slots`, `reset_utc`, `phase`, `schedule`, `labels`. Set `title` to the competition's
   name. Turn the day's slots, the later slots, the research items and the recent decisions into dated `plan` items
   (`when`, `what`, `status`); the compute notes into `resources` rows (what each machine, service or account is,
   from and until, cost, status, what it is used for); open points into `questions`; what the owner must do into
   `owner_actions`. Add `start` (the project's first day), a short `summary` and, when the pack has a spending limit,
   `daily_budget_usd`.
3. Start the cost ledger `<pack>/.memory/spend.jsonl` if it is missing: one JSON line per cost other than Claude Code,
   `{"day": "YYYY-MM-DD", "category": "cloud GPU", "usd": 1.5, "what": "<what it paid for>"}`.
4. Keep the page out of git: add `reports/status*.pdf` and `reports/html/status*.html` to the project's `.gitignore`
   (it shows machines and spend), and `*.json.lock` (the submit lock files) if it is not there yet.
5. Archive the old pages: `git mv` every live-plan PDF (`reports/<name>.pdf`, named by the plan's `name`), every
   phase progress report PDF and their HTML sources under `reports/html/` into `reports/archive/`, and
   `submissions/live-plan.json` with them. Use plain `mv` for a file git does not track.
6. Drop the live plan's and the phase reports' schedule events (the `clock` file's `DAILY` and `DATED` lists,
   `<pack>/.memory/schedule.json`): the hourly pass now rebuilds the status page. In the pack's instructions, briefs
   and scripts, replace `kaggle_live_plan.py` with `kaggle_status.py` (`--keep-rev`, `--no-render` and `--out` work
   as before; `--plan`, `--name`, `--clock`, `--render-env`, `--hosts` and `--leases` are gone: the clock and the
   render env come from the JSON, hosts and lease ends from `<pack>/.memory/`), and `kaggle_hourly.py --plan FILE`
   with `--status FILE`, or no flag for `reports/status.json`. Point every mention of the live plan or a phase
   report at the status page.
7. Build the page from the project root: `python3 <pack>/plugins/kaggle/tools/kaggle_status.py`.
8. Record `{"name": "kaggle", "version": "0.7.0"}` in `<pack>/manifest.json` and re-baseline the `revisions` entries
   for `<pack>/plugins/kaggle/` (`revs baseline` does this, whatever the pack folder is named).

## Validate

- `kaggle_status.py` exits 0, and with the reporting plugin attached `reports/status.pdf` passes the layout check.
- `git check-ignore reports/status.pdf reports/html/status.html reports/status-short.pdf reports/html/status-short.html`
  prints all four paths.
- `python3 <pack>/plugins/kaggle/tools/kaggle_hourly.py <slug>` shows a `status` line with no FLAG.
- Nothing in the project calls `kaggle_live_plan.py` or names `submissions/live-plan.json` any more, and no live-plan
  or phase report PDF is left outside `reports/archive/`.

## Revert

- Restore the 0.6.x copy and the manifest entry `{"name": "kaggle", "version": "0.6.0"}` from the plugin's git history,
  `git mv` the archived live-plan files back, and restore the schedule events and calls. Delete the generated
  `reports/status.pdf` and `reports/html/status.html`. `reports/status.json` and `<pack>/.memory/spend.jsonl` are
  data: keep them.
