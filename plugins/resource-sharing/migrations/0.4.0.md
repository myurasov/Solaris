# resource-sharing 0.4.0 - Host Health by File, Not by Chat <!-- omit in toc -->

- [Migrate](#migrate)
- [Validate](#validate)

For packs updating from 0.3.x. A pack on 0.3.0 or 0.3.1 gets 0.3.2 here too (the skill's check of each GPU repair
with real GPU work, shipped without a migration), with no step of its own. Every message wakes the project it goes
to, so an owner's hourly health reading and a guest's reply that agrees with it cost a turn on each side and say
nothing new. From 0.4.0 the owner keeps the health of its hosts in a file (`hosthealth.py --write`) and messages
guests only when a host crosses a threshold (`TRIPPED` or `CLEARED` lines) or a shared host's availability changes;
guests read the file (`hosthealth.py --shared`). The Xid count now comes from the kernel journal of the current boot
(`dmesg` where the journal cannot be read), and `--hosts NAME[,NAME]` picks hosts by name. Nothing is breaking.

## Moved Paths

None. Two new private files appear in the pack of each project that runs `hosthealth.py --write` (owners):
`<pack>/.memory/host-health.json` (the health guests read) and `<pack>/.memory/host-health-state.json` (what the
next check compares against). Both stay out of git with the rest of `<pack>/.memory/`.

## Pre-flight

- The project has this plugin copied at `<pack>/plugins/resource-sharing/` (`<pack>`: the project's ai-pack
  folder). Live claims may stay up: nothing here touches them.
- List where the project runs the health check and where it sends or answers health messages:
  `grep -rn "hosthealth\|health" <pack>/instructions.md <pack>/.memory/schedule.json tools/` (skip what does not
  exist), plus any standing arrangement with another project about hourly readings in the project's own notes.
- Update every project that shares the same hosts together where possible: a guest still on 0.3.x has no
  `--shared` and finds no file to read.

## Migrate

1. Update the copy (`install-plugin` update): every `shared/` file of 0.4.0 into `<pack>/plugins/resource-sharing/`.
2. **Owners** (a project with hosts in `share_with`, or any project that wants the file): make the hourly check
   `python3 <pack>/plugins/resource-sharing/tools/hosthealth.py --fix --write`. Send the projects you share with
   only its `TRIPPED` and `CLEARED` lines (the output names the `share_with` projects to send them to) and changes to
   a shared host's availability (it stops answering or comes back, is drained, retired, rebooted for repair, or its
   lease ends sooner).
3. **Guests**: read `python3 <pack>/plugins/resource-sharing/tools/hosthealth.py --shared` at the hourly pass (a
   Kaggle project's STATUS block and status page read the same file, kaggle 0.10.0). Treat a `bad` host as a
   `TRIPPED` message: start nothing new there and move work off it; exit 3 on a stale or missing reading means
   asking the owner whether its checks still run.
4. **Both**: stop sending each other hourly health readings and "concur" or agreement replies. Remove those steps
   from `<pack>/instructions.md`, the schedule and the project's notes, and tell the other projects once, in one
   message, that health now goes by file.
5. Optional: override thresholds per project as `"hosthealth.<key>"` in `<pack>/.memory/config.json` (the skill's
   Sharing Host Health has the table; 0 turns one off). A value the tool cannot use stops it with exit 2 before any
   check.
6. Optional: replace one-host inventory files made for a single check with `--hosts NAME[,NAME]`.
7. Record `{"name": "resource-sharing", "version": "0.4.0"}` in `<pack>/manifest.json` and re-baseline the
   `revisions` entries for `<pack>/plugins/resource-sharing/` (`revs baseline`).

## Validate

- An owner's `hosthealth.py --fix --write` writes `<pack>/.memory/host-health.json` with an entry per host checked
  and prints the Xid source (`Xid from journalctl -k -b 0` or `Xid from dmesg`); a second run soon after prints no
  `TRIPPED` line for a host whose health held.
- A guest's `hosthealth.py --shared` lists each host shared with it with its health and the reading's age (exit 0
  when every one is `ok` and fresh).
- The pre-flight grep finds no step that sends, asks for or acknowledges hourly health readings.

## Revert

- Restore the 0.3.x copy and the manifest entry from the plugin's git history, and the hourly check without
  `--write`. The two health files are then unread and can be deleted; `hosthealth.*` keys are ignored by 0.3.x.
  Whether hourly health messages come back is the owner's call.
