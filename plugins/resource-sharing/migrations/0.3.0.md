# resource-sharing 0.3.0 - Claims Tied to Their Jobs <!-- omit in toc -->

- [Moved Paths](#moved-paths)
- [Pre-flight](#pre-flight)
- [Migrate](#migrate)
- [Validate](#validate)
- [Revert](#revert)

For packs updating from 0.2.x. A claim's memory is now its processes' PSS (summed RSS where PSS cannot be read);
cores a running job is pinned to are never granted to another claim (only to a new claim of that job); a repeat
`claim --pid` attaches a process to a live claim; `renew` changes a live claim in place; paired claims yield in a set
order (`--yield-with`); `status --json` gives each GPU's last claim end; `hosthealth --power max` holds GPU power
limits at the most each GPU allows, on hosts the project owns only.

## Moved Paths

None. Claim files keep their place and format: the new fields are optional, and claims written by 0.2.x load and
renew as before.

## Pre-flight

- The project has this plugin copied at `<pack>/plugins/resource-sharing/` (`<pack>`: the project's ai-pack
  folder). Live claims may stay up: nothing here releases them.
- List the project's own scripts and notes that renew claims by running `claim` again in a loop, and the jobs started
  outside `run` that should be tied to their claims.

## Migrate

1. Update the copy (`install-plugin` update): every `shared/` file of 0.3.0 into `<pack>/plugins/resource-sharing/`.
2. Replace loops that re-run `claim` to keep a claim alive with `renew --host H --job J --until <end>` (or
   `--hours H`); tie each long-lived job started outside `run` to its claim with `claim --pid <pid>` (look for the
   `attached pid N` line) or `renew --pid <pid>`.
3. Where two claims only work together (a server and the queue that calls it), name the order with `--yield-with`.
4. Owners who want GPU power limits at the maximum set `"policy": {"health": {"power": "max"}}` in
   `<pack>/.memory/resource-sharing.json` (or pass `--power max`); guests' hosts keep the default.
5. Until every project that shares the same hosts runs 0.3.0: a yield sent from a 0.2.x copy skips the pairing, and a
   0.2.x copy reads only a claim's first process. Watchers started before the update keep their old code until
   their jobs end. Hosts may show fewer free cores (a lapsed claim's still-running pinned job keeps its cores) and
   more free RAM (PSS counts shared memory once).
6. Record `{"name": "resource-sharing", "version": "0.3.0"}` in `<pack>/manifest.json` and re-baseline the
   `revisions` entries for `<pack>/plugins/resource-sharing/` (`revs baseline`).

## Validate

- `python3 <pack>/plugins/resource-sharing/tools/hostclaims.py status --json` lists each GPU's `last_claim_end` and
  each claim's `mem_source`.
- No project script still renews a claim by re-running `claim` in a loop.

## Revert

- Restore the 0.2.x copy and the manifest entry from the plugin's git history. Claims written by 0.3.0 keep working
  under 0.2.x, which ignores the new fields.
