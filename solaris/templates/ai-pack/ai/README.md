This folder is the **ai-pack** for **{{NAME}}** ({{TYPE}}, {{MODE}} mode) — everything an AI
coding agent needs to work on this project consistently: who the agent is, the rules it follows,
the project's spec, and its private memory. Generated by Solaris v{{FRAMEWORK_VERSION}}, and
standalone-first: it works with just this project checked out, no framework around it.

## What This Is

An agent session starts at the project root's `AGENTS.md`, which points into this folder. The
pack then does three jobs: it defines the **engineer persona** the agent adopts
(`engineer.agent.md`), it carries the **project knowledge** the agent needs (spec, instructions,
memory), and it enforces the **working rules** — commit policy, safety, git workflow, and the
always-on rules in `rules/`.

This file is generated and re-rendered when the pack updates, so put durable notes in
`engineer.instructions.md` instead of editing it. Files carry Solaris sync metadata
(`_Rev. N_` markers, the `revisions` map in `manifest.json`) — leave that as-is.

## Configuration

Behavior switches live in `defaults.json` (committed, shared with the team); a private
`.memory/config.json` overrides them per key on this machine:

| Key | Default | Meaning |
|---|---|---|
| `git.developer_branches` | `true` | Everyone works on a personal `<id>-develop` branch; commits never land on `main` directly. |
| `git.feature_branches` | `true` | Larger features get their own `feature-<descr>` branch. |
| `subagents.level` | `auto` | How aggressively work is delegated to subagent models (`off`/`auto`/`quality`/`cost`). |
| `economy.level` | `med` | Token-frugality level (`off`/`med`/`full`/`auto`). |
| `yagni.enabled` | `false` | When on: deliver exactly what was asked, in the smallest coherent form. |

Machine-specific facts (hosts, URLs, accounts) go in `.memory/resources.md` — the init skill
fills them in; secrets only ever in `.memory/credentials.md` (gitignored). MCP servers are
configured in the project root's `.mcp.json` / `.cursor/mcp.json` (also machine-local).

## How-To: Everyday Workflows

Each workflow below is a skill or rule the agent already knows — just say the trigger phrase.

### Set Up a Fresh Checkout (init)

Say **"init project"** or **"onboard me"**. The agent collects the resources this project needs
(hosts, services — any can be skipped), writes the private `.memory/` layer, sets up your
personal git branch, and brings the environment up. Details: `skills/init.skill.md`.

### Stay Up to Date (refresh)

Say **"refresh"** or **"pull latest"**. The agent pulls `main`, brings your personal branch up
to date (handling rewritten upstream history safely), migrates your local copy to any new
layouts, and reports what changed. It never pushes. Details: `skills/refresh.skill.md`.

### Work with Git

Per `rules/git-collab.rule.md`: you work on a personal `<id>-develop` branch the agent creates
automatically; commits there are automatic — single-line, imperative; **nothing is ever pushed
without an explicit ask**. To contribute back, ask for a PR. Feature work goes on
`feature-<descr>` branches and merges back with a merge commit when done.

### Update the Pack Itself

Under a Solaris checkout, say "update `<project>`": Solaris syncs the pack's managed files
per-file (untouched files fast-forward, your improvements merge upstream, real conflicts ask)
and applies any framework migrations — this README re-renders with the current plugin list.
Standalone, just edit files normally and leave the sync metadata alone.

## Privacy: Memory, Logs, and Secrets

`.memory/` is the pack's private layer: `context.md` (session context), `resources.md` (your
machine's hosts and paths), `credentials.md` (secrets — never committed, never echoed),
`interactions.jsonl` (work log), `config.json` (per-machine switch overrides), and `spec-v0.md`
(the initial spec, captured at creation). It stays on your machine; everything else in this
folder is the shareable part of the pack.
