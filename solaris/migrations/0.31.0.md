## Summary

Framework 0.31.0 adds the bundled **`appstore-connect` plugin** - field-tested App Store Connect
operation from the developer's perspective as separate shared files: `asc-api.skill.md` (ASC REST
API, the default path), `browserctl.asc.skill.md` (browser flows the API cannot reach, in the new
browser-control extension-skill format `browserctl.<site>.skill.md`), `asc-upload.skill.md`
(archive + upload a build), and the always-on `asc.rule.md`. The base `browserctl` plugin is a
prerequisite for the browser skill. No ai-pack schema change; this is a **marker migration** -
existing projects need no file edits. Attaching the plugin is opt-in via `install-plugin`.

## Pre-flight Checks

- [ ] `ai/manifest.json` exists and is valid JSON.

## Migrate

1. Nothing mandatory. Optionally attach the new plugin: `install-plugin` ("add plugin
   appstore-connect to `<project>`", or "link plugin appstore-connect to `<project>`" while
   developing it) - attach the base `browserctl` plugin first.
2. `uv run -m solaris.tools.version set --dir projects/<slug> 0.31.0`.

## Validate

- [ ] `uv run -m solaris.tools.revs classify --dir projects/<slug>` runs clean.
- [ ] `uv run -m solaris.tools.version check --dir projects/<slug>` exits 0.

## Revert

1. If the plugin was attached during this migration: detach it (remove `ai/plugins/appstore-connect/`
   or the `ai/plugins/appstore-connect.link.md` pointer, and the manifest `plugins[]` entry), then
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
2. `uv run -m solaris.tools.version set --dir projects/<slug> 0.30.8`.
