## Summary

Framework 0.41.0 makes the owner-directions log private, adds a private improvements file, and splits the
interaction log per machine. Below, `<pack>/` is the project's ai-pack folder (default `aipack/`, `ai/` in
projects made before 0.39.0, any name).

- **Owner-directions log, now private:** `<pack>/.memory/directions.md` replaces `<pack>/directions.md`,
  which went into git wherever the pack is kept in git. The persona still logs each direction the moment the
  owner gives it; directions meant to last are folded into `<pack>/instructions.md`, the shareable store for
  long-standing instructions.
- **Improvement suggestions:** project work never edits framework files (anything of the Solaris checkout
  outside the project, and the pack's managed copies) unless the owner allows that change in their own words.
  A project writes its suggestions for the framework or its plugins, and nothing else, to the private
  `<pack>/.memory/improvements.md`; the orchestrator reviews them on "review project improvements" and
  implements only what the owner approves.
- **Interaction logs, one file per machine:** `uv run -m solaris.tools.interactions add --dir projects/<slug>`
  writes `<pack>/.memory/interactions/<machine>.jsonl`, so a folder synced between machines never has two
  writers on one file; the old `<pack>/.memory/interactions.jsonl` stays as read-only history.

The managed pack files move forward: the primary persona (rev 47: the framework-files boundary, the private
directions log, per-machine logging), the project-root `AGENTS.md` (rev 23), `<pack>/README.md` (rev 10),
`<pack>/rules/token-economy.rule.md` (rev 5), and the skills `handover` (rev 4: closing browsers at a pause),
`init` (rev 12) and `refresh` (rev 11), whose new log line is their only template change.

Five bundled plugins advance, none with a plugin migration: **`kaggle` 0.6.0** (its always-on rule adds "no
forgotten browsers", its hourly pass flags this project's browsers up over two hours and report-render Chromes
an interrupted render left, and the playbook gains lessons), **`reporting` 0.4.0** (the renderer closes its
Chrome when it exits or is stopped, and first closes any Chrome an interrupted render left, whichever project
it served; `render.sh --reap` does only that cleanup; the stylesheet avoids one-word last lines and lets a tall
row of a split table break across pages), **`nvidia-brev` 0.1.5** (notes on copies to an instance with port 22
closed or a changed home path, and per-machine logging), **`apple-asc` 0.1.2** and **`gmail` 0.1.2**. The
kaggle, reporting, apple-asc and gmail skills now have a project suggest plugin changes instead of editing the
plugin. No manifest schema change.

## Migrate

1. Directions log: if `<pack>/directions.md` exists, move it to `<pack>/.memory/directions.md`, appending its
   entries to an existing one rather than overwriting it. If neither exists, copy
   `solaris/templates/ai-pack/ai/.memory/directions.md` there with `{{NAME}}` replaced by the project's name
   (`project.name` in `<pack>/manifest.json`).
2. Improvements file: if `<pack>/.memory/improvements.md` is missing, move a stray `<pack>/improvements.md`
   there whole, or else seed it from `solaris/templates/ai-pack/ai/.memory/improvements.md` with `{{NAME}}`
   filled. Then append any stray `<pack>/improvements.md` or `<pack>/lessons.md` still in the pack to it
   whole, and remove the stray file. Never overwrite an existing file and never drop an entry: step 5 moves
   what is not a suggestion into `instructions.md`.
3. For each of `kaggle`, `reporting`, `nvidia-brev`, `apple-asc` and `gmail` attached in copy mode, update it
   through `install-plugin` ("update plugin `<name>` in `<project>`"): it resolves any `merge-up` /
   `conflict` rows under `<pack>/plugins/<name>/`, runs `revs ff` (which syncs the whole pack), and records
   the new version in the manifest's `plugins[]` entry, patch releases included: `kaggle` `0.6.0`,
   `reporting` `0.4.0`, `nvidia-brev` `0.1.5`, `apple-asc` `0.1.2`, `gmail` `0.1.2`. None ships a plugin
   migration, and saved plugin state carries over. Link-mode installs follow the plugin source and need
   nothing. One behavior change to pass on: the kaggle hourly pass now also flags this project's browsers up
   over two hours and leftover report-render Chromes, exiting 10 like any other flag; stop what no running
   task needs.
4. `uv run -m solaris.tools.revs ff --dir projects/<slug>` (the `update-project` revision sync)
   fast-forwards the managed files listed above; a file edited since the last baseline classifies as
   `merge-up` / `conflict` and is resolved per `update-project` step 1 instead (a merged copy that keeps
   project hunks needs its `_Rev. N_` raised above the master's, or the next ff replaces it). Then
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
5. Hand the rest to the project's own session: fold the long-standing entries of `.memory/directions.md` into
   `<pack>/instructions.md`; move the entries of `.memory/improvements.md` that are not suggestions for the
   framework or a plugin into `<pack>/instructions.md` (or `.memory/context.md`); in a kept filled-in stub,
   replace a line that logs to `interactions.jsonl` with the template's new one (log in this machine's file in
   `<pack>/.memory/interactions/`). Where the pack is kept in git, commit the managed-file update together
   with the removal of the old `<pack>/directions.md` (and of a moved `improvements.md` or `lessons.md`).
6. `uv run -m solaris.tools.version set --dir projects/<slug> 0.41.0`, then run
   `uv run -m solaris.tools.revs ff --dir projects/<slug>` and
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>` again: `<pack>/README.md` and
   `<pack>/<primary>.agent.md` print the framework version from the manifest.

## Revert

`apple-asc` 0.1.1, `gmail` 0.1.1). There, a pack file whose rev is above its master classifies as `merge-up`
and never fast-forwards backwards, so step 2 removes the newer copies first.

1. Move `<pack>/.memory/directions.md` back to `<pack>/directions.md`, and commit it where the pack is kept in
   git: 0.40.0 personas read the log there. `<pack>/.memory/improvements.md` can stay; 0.40.0 ignores it.
2. Restore the managed files and copied plugins from before Migrate steps 3 and 4: git revert of the update,
   or delete each file those steps fast-forwarded and let `revs ff` in Revert step 4 write it back from the
   0.40.0 masters (re-apply by hand any project edits they merged). Set each updated plugin's `plugins[]`
   version in `<pack>/manifest.json` back. In a kept filled-in stub, put the old log line back: 0.40.0 has no
   `solaris.tools.interactions`, and its sessions append to `<pack>/.memory/interactions.jsonl`.
3. `uv run -m solaris.tools.version set --dir projects/<slug> 0.40.0`.
4. `uv run -m solaris.tools.revs ff --dir projects/<slug>`, then
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
