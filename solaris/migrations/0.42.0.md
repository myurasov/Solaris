## Summary

Framework 0.42.0 fixes the session hooks and adds housekeeping. Below, `<pack>/` is the project's ai-pack folder.

- **Hooks:** the Claude Code hooks now run `uv run --directory "${CLAUDE_PROJECT_DIR:-.}" -m solaris.tools.<name>`.
  Before, every hook failed with "No module named 'solaris'" whenever the session's shell sat in a project folder,
  so skills did not load, rule reminders and the backup log line were lost, and the read-first files were not
  restored after a compaction. The change is in the framework root; packs need nothing.
- **Housekeeping:** the stdlib tool `solaris.tools.housekeeping --dir projects/<slug> [report|tidy|prune]` keeps a
  project within its data budget and its private folder in order. `report` is read-only; `tidy --apply` moves
  leftovers out of the `<pack>/.memory/` root into `.memory/archive/<YYYY-MM>/` and job scratch into `__out/jobs/`;
  `prune --apply` deletes only by the rules in the optional `<pack>/housekeeping.json` and by `.disposable`
  markers. A project with files it still reads in the `.memory/` root lists them under `memory_allow` first.
- **Primary persona (rev 48):** re-read the pack after any framework or plugin update; rewrite `context.md` as a
  snapshot at every periodic pass and milestone (automatic compaction gives no save turn); committed code and docs
  never read a session scratchpad; run housekeeping (report daily, tidy at handovers); no banner comment lines.
- **Handover skill (rev 5):** the note lists every managed file `revs classify` reports as not in sync, with why it
  was edited; a pause tidies the private folder; a resume after an update re-reads the pack first.
- **Project-root `AGENTS.md` (rev 24):** framework tools from any folder run as
  `uv run --directory <solaris root> -m solaris.tools.<name>`.
- **Model tiers (`<pack>/info/model-tiers.md`, rev 9):** the mid tier is Sonnet 5.5 again; the owner lifted its
  avoidance on 2026-10-05 (Fable 5 and 5.1 stay excluded unless the owner asks).
- **New packs only** (seed files, never synced into existing packs): `instructions.md` opens with an "Owner's
  Standing Rules" section, and the `.memory/context.md` seed has the snapshot shape. Existing packs may copy both.
- **Plugins:** `kaggle` 0.7.0 replaces the live plan and phase reports with one status page and adds the owner's
  standing Kaggle directives to its always-on rule (rev 9: technical-only jobs on Sonnet 5.5); run its own
  `migrations/0.7.0.md`. Other attached plugins at a newer version follow their own migrations.
