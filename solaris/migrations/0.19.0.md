## Summary

The framework's own memory folder moves from `memory/` to `.memory/` (matching the ai-pack's
`ai/.memory/`); this is framework-internal - the `read_first` session hook auto-renames a legacy checkout
on first access, so no per-project action is needed for it. For ai-packs this release is additive: the
template now ships two pack-level skill stubs - `ai/init.skill.md` (one-time environment onboarding for a
fresh checkout) and `ai/refresh.skill.md` (pull + migrate + verify for a returning teammate) - plus
"Local-Only Folders" (`__*/`, gitignored) and "Remote Host Discipline" sections in
`engineer.instructions.md` (seed-time content; existing projects adopt those sections by hand if wanted).
v0.19.0 also adds the `publish-project` skill and rule/tool hardening - none of which needs migration.

## Pre-flight checks

- [ ] `ai/manifest.json` exists and is valid JSON.
- [ ] `uv run -m solaris.tools.revs classify --dir projects/<slug>` shows no unresolved `conflict` rows.

## Migrate

1. Sync materialized files by revision (brings `AGENTS.md` / `ai/engineer.agent.md` to the 0.19.0 revs):
   `uv run -m solaris.tools.revs ff --dir projects/<slug>`.
2. **Optional (recommended):** copy the new pack-level skill stubs into projects that want them - from
   `solaris/templates/ai-pack/ai/`: `init.skill.md` and `refresh.skill.md` into `projects/<slug>/ai/`
   (substitute `{{NAME}}`), then fill in the project-specific steps. Skip for packs that already carry
   their own `init`/`refresh` skills.
3. Record the version: `uv run -m solaris.tools.version set --dir projects/<slug> 0.19.0`.

## Validate

- [ ] `uv run -m solaris.tools.version check --dir projects/<slug>` exits 0.
- [ ] `uv run -m solaris.tools.revs classify --dir projects/<slug>` reports in-sync.

## Revert

Set `framework_version` back to `0.18.0` in `ai/manifest.json` and delete the copied
`ai/init.skill.md` / `ai/refresh.skill.md` if they were added. The framework-side folder rename reverts
with `mv .memory memory` (not recommended - the 0.19.0 tools read `.memory/`).
