## Summary

Framework 0.37.0 gives every persona of a pack **one shared instructions store**, `ai/instructions.md`,
replacing `ai/<primary>.instructions.md` and the 0.36.0 per-role `ai/agents/<role>.instructions.md`
files: whoever learns a durable lesson writes it there once (a persona running without write access hands
it back in its report for the primary to apply), so no persona repeats another's mistake and nothing is
kept twice; procedure that only one role runs sits under a heading named for that role, in the same file.
Role briefs move from `ai/agents/<role>.agent.md` to `ai/<role>.agent.md`, beside the primary persona -
every `ai/*.agent.md` other than the primary's is a role. `solaris.tools.agents --check` reports the old
layout (a leftover `ai/agents/`, a per-persona instructions file, a missing `ai/instructions.md`) as
problems until this migration is applied. Packs without role personas only rename one file.

## Pre-flight Checks

- [ ] `ai/manifest.json` exists and is valid JSON; note the primary persona's name (`agents.primary`, or
      `engineer`).
- [ ] `uv run -m solaris.tools.revs classify --dir projects/<slug>` shows no `conflict` rows.
- [ ] The pack is committed (or backed up): step 2 merges file contents by hand.

## Migrate

`git mv` below assumes the pack is git-tracked; under a Solaris checkout `projects/` is gitignored, so
use plain `mv` (and `rmdir`) there - the result is the same.

1. Rename the primary's instructions file: `git mv ai/<primary>.instructions.md ai/instructions.md`.
   Retitle its H1 to `# Instructions - <Project>`, set the marker to `_Rev. 12_`, and replace the intro's
   first two paragraphs with the template's (`solaris/templates/ai-pack/ai/instructions.md`: the one shared
   "how" layer for every persona; lessons land here once), substituting `{{NAME}}` and `{{PRIMARY}}` by
   hand. Repoint references to the old name elsewhere in the pack:
   `grep -rn '<primary>.instructions.md' <project> --include='*.md' --exclude-dir=.git` (`ai/spec.md`,
   `ai/.memory/context.md`, `ai/.memory/resources.md`, workspace READMEs).
2. For each `ai/agents/<role>.instructions.md` (0.36.0 packs only): fold its content into
   `ai/instructions.md` - general lessons into the matching sections (Runtime Notes & Gotchas, Remote Host
   Discipline, Conventions), role-only procedure under a new `## <Role> ...` heading - then delete the file.
3. For each `ai/agents/<role>.agent.md`: `git mv ai/agents/<role>.agent.md ai/<role>.agent.md`; inside the
   brief, replace `agents/<role>.instructions.md` / `<role>.instructions.md` pointers with
   `instructions.md`. Then `rmdir ai/agents`.
4. `uv run -m solaris.tools.revs ff --dir projects/<slug>` then
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>` - re-renders `AGENTS.md`, the primary
   persona, `ai/README.md`, the subagents rule, and the init stub with the new layout.
5. `uv run -m solaris.tools.agents --check --dir projects/<slug>` exits 0 (no `PROBLEM:` lines).
6. `uv run -m solaris.tools.version set --dir projects/<slug> 0.37.0`.

## Validate

- [ ] `uv run -m solaris.tools.version check --dir projects/<slug>` exits 0.
- [ ] `uv run -m solaris.tools.agents --check --dir projects/<slug>` exits 0 and lists every role.
- [ ] `ls projects/<slug>/ai/*.instructions.md` matches nothing (the shared file is `ai/instructions.md`,
      with no persona name in front); `ai/agents/` is gone.
- [ ] `ai/README.md` (Personas) links `<role>.agent.md` for every role and names `instructions.md`.

## Revert

Presumes the framework checkout is back on 0.36.0.

1. Restore the pre-migration pack from your backup or commit: `ai/<primary>.instructions.md` (H1 and
   intro included), each `ai/agents/<role>.agent.md`, and the per-role `ai/agents/<role>.instructions.md`
   files (the merge in step 2 is not mechanically reversible); delete `ai/instructions.md` and the moved
   `ai/<role>.agent.md` briefs.
2. Restore the five re-rendered managed files (`AGENTS.md`, `ai/<primary>.agent.md`, `ai/README.md`,
   `ai/rules/subagents.rule.md`, `ai/skills/init.skill.md`) from the same source - `revs ff` never renders
   backwards (a pack file ahead of its master classifies `merge-up` and is skipped) - then
   `uv run -m solaris.tools.version set --dir projects/<slug> 0.36.0` and
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
