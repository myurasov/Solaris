## Summary

Framework 0.23.0 groups projects one level below `projects/` (`projects/<group>/<slug>/`), files tasks by
month (`tasks/<YYYY>/<MM>/`), adds an always-on interaction rule and Long-Running Remote Work safety
duties (both embedded in the engineer template, rev 30), makes interaction-log timestamps UTC, and teaches
the skill-loader hook to inject a per-project overlay index. For an existing project this is a
content-only template sync plus one path check; no ai-pack schema change.

## Pre-flight Checks

- [ ] `ai/manifest.json` exists and is valid JSON.
- [ ] `uv run -m solaris.tools.revs classify --dir <project>` runs clean (no unresolved conflicts).

## Migrate

1. Sync the template: `uv run -m solaris.tools.revs ff --dir <project>` (brings `ai/engineer.agent.md`
   rev 30: Interaction Policy section + remote-work duties in the Safety Policy). Resolve any
   `merge-up`/`conflict` per `update-project`.
2. **If the project folder was moved into a group** (`projects/<group>/<slug>/`): for each linked plugin
   pointer `ai/<name>.link.md`, verify the plugin-root path still resolves from the ai-pack root
   (`ls <ai-pack root>/<path>`); a grouped project needs `../../../plugins/<name>/` (one more `../` in
   embedded mode). Fix the depth if stale.
3. Re-record the baseline: `uv run -m solaris.tools.revs baseline --dir <project>`.
4. `uv run -m solaris.tools.version set --dir <project> 0.23.0`.

## Validate

- [ ] `ai/engineer.agent.md` shows `_Rev. 30_` and contains an "Interaction Policy" section.
- [ ] Every `ai/*.link.md` plugin-root path resolves.
- [ ] `uv run -m solaris.tools.version check --dir <project>` exits 0.

## Revert

1. Restore the previous `ai/engineer.agent.md` from git (or the prior baseline) and re-run
   `revs baseline --dir <project>`.
2. `uv run -m solaris.tools.version set --dir <project> 0.22.3`.
