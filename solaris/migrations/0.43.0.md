## Summary

Framework 0.43.0 tightens skill auto-load and the logging and revision tools, and leaves the effort level to the
owner. Below, `<pack>/` is the project's ai-pack folder.

- **Skill auto-load:** a `<project>` placeholder in a skill trigger matches only a real project (its slug,
  `<group>/<slug>` or a path ending at it) or the nouns project, repo and pack; other placeholders never take a
  function word; turns the owner did not type (task notifications, subagent and peer-session messages, compaction
  summaries, interrupt notes, subagent reports) load nothing. The change is in the framework root; packs need
  nothing.
- **Revisions:** `revs ledger --plugin <name>` rebuilds one plugin's ledger; `revs bump` keeps the final newline of
  Markdown files with frontmatter.
- **Interaction log:** `interactions add` takes an optional `--trigger owner|clock|worker|peer` (stored as `trigger`)
  and refuses an empty or `-` project (exit 2). The primary persona (rev 49) names the optional field.
- **Spend tool:** `ai_spend --detail` adds the main thread's models and efforts, each worker's model, effort and spend,
  and the hook runs with their failures.
- **Migrations:** each migration lists its Moved Paths; `update-project` greps every pack for the old paths.
- **Effort (owner, 2026-10-08):** the effort level is the owner's choice per session. The model tiers (rev 10) fix no
  level; nothing in the framework or the plugins does.
- **Plugins:** `kaggle` 0.8.0 splits the playbook into a core read every session, four kind skills and a kernel skill,
  and gives the hourly pass a STATUS block and new flags (run its `migrations/0.8.0.md`); `resource-sharing` 0.3.0
  ties claims to their jobs: PSS memory, `claim --pid` to attach a process, `renew`, paired yields, cores held by a
  running job never granted to another claim, `hosthealth --power max` on owned hosts (run its `migrations/0.3.0.md`);
  `nvidia-brev` 0.1.6 and `browserctl` 0.2.3 add field lessons.

## Migrate

1. `uv run -m solaris.tools.revs ff --dir projects/<slug>` (persona rev 49, model tiers rev 10, and the copy-mode
   plugin overlays), resolving `merge-up` and `conflict` files as noted.
2. For an attached `kaggle` plugin in copy mode, apply `plugins/kaggle/migrations/0.8.0.md`; for `resource-sharing`,
   `plugins/resource-sharing/migrations/0.3.0.md` (the project's own session does their project-side steps).
3. Record the plugin versions in `<pack>/manifest.json` `plugins[]`, then
   `uv run -m solaris.tools.version set --dir projects/<slug> 0.43.0`, `revs ff` and `revs baseline` again.
4. The project's own session, after the update: re-read the pack; reword any line of the pack's own files that fixes
   an effort level ("max effort", "restart at max") to "the effort the owner chose", keeping registry tags; log with
   `--trigger` where it helps.

`revs ff` and `revs baseline`, and `version set 0.42.0`. The plugin migrations say how to revert their copies.
