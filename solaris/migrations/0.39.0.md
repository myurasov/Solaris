## Summary

Framework 0.39.0 makes the ai-pack folder name free: a project's pack is the one direct child folder of
the project root whose `manifest.json` is an ai-pack manifest (it has `framework_version` and a `project`
object), so new projects default to `aipack/` and any plain folder name works. Below, `<pack>/` is the
project's ai-pack folder (default `aipack/`, `ai/` in projects made before 0.39.0, any name). Existing
projects keep their folder - this migration renames nothing, and no step here is needed for it. Renaming is
optional, at any time, through `update-project` step 4: run `revs ff` and `revs baseline` first, add
ignore entries for the new folder name beside the old ones (`.gitignore`, `.stignore`, `.git/info/exclude`
where used), run `uv run -m solaris.tools.agents --rename-pack <name> --dir projects/<slug>` (it refuses,
moving nothing, while the new folder's `.memory/` would not be ignored), then `revs ff` (merging anything it
reports) and `revs baseline`, and remove the old ignore entries last.

The release also adds an always-on **Stopped or Failed Subagents** section to the pack's subagents rule
(`<pack>/rules/subagents.rule.md` rev 7): a subagent that ends without its deliverable is salvaged, then
recovered or re-run (the brief reworded before a retry, at most two retries), and tracked until it is
recovered, re-run, or reported as abandoned; the pack's model tiers (`<pack>/info/model-tiers.md` rev 7) run the
frontier tier on Opus 5.5 at `max` effort and avoid Fable 5.x unless the owner explicitly asks. The bundled
**`kaggle` plugin** moves to 0.4.0: three fixed read-only SDK reads behind its gateway (`--sdk`: `topic`,
`notebooks`, `account`) let the forum watch read each topic once in full, `kaggle_lb.py notebooks <slug>`
save public notebook scores over time and `kaggle_share.py` scan the account in one read, while commands and
every write stay on the CLI; it also adds a live plan page (`tools/kaggle_live_plan.py`), playbook lessons,
and hourly checks at the agent's hourly pass instead of cron or launchd. The rest of the release (a
four-part read-first load with a Syncthing conflict sweep, a shared `.stglobalignore`, plugin tests at
release) is framework-side. No ai-pack schema change, so this is a marker migration: the two pack files
arrive through the usual revision sync, and a copied `kaggle` overlay is a plain copy update with no plugin
migration.

## Migrate

1. If the project has `kaggle` attached in copy mode, update it to 0.4.0 through `install-plugin` ("update
   plugin kaggle in `<project>`"): it resolves any `merge-up` / `conflict` rows under `<pack>/plugins/kaggle/`,
   fast-forwards the rest (adding `tools/kaggle_sdk.py` and `tools/kaggle_live_plan.py`), and records
   version `0.4.0` in the manifest's `plugins[]` entry. 0.4.0 ships no plugin migration; the plugin's saved
   state from 0.3.0 carries over. Link-mode installs follow the plugin source and need nothing.
2. `uv run -m solaris.tools.revs ff --dir projects/<slug>` (the `update-project` revision sync)
   fast-forwards `<pack>/rules/subagents.rule.md` and `<pack>/info/model-tiers.md` to rev 7 and re-renders the
   `<pack>/README.md` plugin list; a user-edited copy classifies as `merge-up` / `conflict` and is resolved per
   `update-project` step 1 instead. Then `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
3. `uv run -m solaris.tools.version set --dir projects/<slug> 0.39.0`.

## Revert

Presumes the framework checkout is back on 0.38.4 (kaggle plugin 0.3.0). The 0.38.4 tools only find a pack
named `ai/`, so a pack renamed after this migration is renamed back first, while the checkout is still on
0.39.0, through `update-project` step 4 (`revs ff` and `revs baseline`, ignore entries for `ai/` added beside
the current ones, `uv run -m solaris.tools.agents --rename-pack ai --dir projects/<slug>`, `revs ff`,
`revs baseline`, then the entries for the other name removed).

1. Restore the rev 5 `<pack>/rules/subagents.rule.md` and `<pack>/info/model-tiers.md` (git revert of the update, or
   copy both from `solaris/templates/ai-pack/ai/`).
2. If Migrate step 1 updated a copied `kaggle` overlay: restore `<pack>/plugins/kaggle/` the same way (git
   revert, or copy `plugins/kaggle/shared/` over it and delete `tools/kaggle_sdk.py` and
   `tools/kaggle_live_plan.py`), and set its `plugins[]` version in `<pack>/manifest.json` back to `0.3.0`.
3. `uv run -m solaris.tools.revs ff --dir projects/<slug>` (re-renders the `<pack>/README.md` plugin list), then
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
4. `uv run -m solaris.tools.version set --dir projects/<slug> 0.38.4`.
