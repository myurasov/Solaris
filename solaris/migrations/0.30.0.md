## Summary

0.30.0 adopts a token-economy rule family. A new always-on pack rule `ai/rules/token-economy.rule.md`
(read budget, unbounded-file discipline, batching, leveled frugality measures, pacing; key
`"economy.level"` off/med/full/auto, absent = `med`) joins the pack, and `ai/rules/subagents.rule.md`
is rewritten around it: an always-on bulk-read floor (a >~20k-token lookup runs in a subagent; ~10k at
economy `full`) plus postures `off/auto/quality/cost` (absent = `auto`, which follows the resolved
economy level; old values `med`/`full` keep working as aliases for `quality`/`cost`). Risk is minimal:
rule fast-forwards plus two `ai/defaults.json` keys.

## Pre-flight checks

- [ ] `ai/manifest.json` exists and is valid JSON.
- [ ] `ai/defaults.json` exists and is valid JSON.

## Migrate

1. `uv run -m solaris.tools.revs ff --dir projects/<slug>` - copies the new
   `ai/rules/token-economy.rule.md` (rev 1) and fast-forwards `ai/rules/subagents.rule.md` (rev 3),
   `ai/engineer.agent.md` (rev 39), and `ai/info/harnesses.md` (rev 2). User-edited copies classify as
   merge-up/conflict per the normal revisions flow instead.
2. Edit `ai/defaults.json`: add `"economy.level": "med"` and set `"subagents.level": "auto"`. If the
   project deliberately pinned a posture, keep the pin - old values stay valid as aliases
   (`med` = `quality`, `full` = `cost`).
3. Private `ai/.memory/config.json` overrides need no change (same aliases apply); set per-machine
   levels there if this machine wants something other than the committed defaults.

1. Restore the previous `ai/defaults.json` values (drop `"economy.level"`, restore the prior
   `"subagents.level"`).
2. Restore the four rule/agent/info files from the previous framework version (git revert of the
   update commit, or re-run `revs ff` from a 0.29.0 checkout) and re-record the baseline:
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
