## Summary

Framework 0.45.0 keeps unattended project sessions awake and gives them back their own rules after a compaction.
Below, `<pack>/` is the project's ai-pack folder and `<project>` its path from the Solaris root.

- **Session clock:** `uv run -m solaris.tools.session_clock --dir <project>` now writes
  `<pack>/.memory/clock.json`, registers the Claude Code session (by `CLAUDE_CODE_SESSION_ID`) in
  `~/.cache/solaris/sessions/`, keeps one clock per project (a new start stops the older one), and ends each run
  with the exact next command. New: `--status`, `--stop`, `--check` (a dry test that arms nothing), `--forget`
  (ends the session's project mode), `--cap 0` (no cap). In Claude Code interactive sessions (terminal, IDE
  extension, desktop; 2.1.288 and later) background commands have no time limit: start the clock with
  `--cap 55`, so a turn still comes at least every 55 minutes. Start it as the harness's own background command,
  alone in its call: never with `&`, `nohup`, `disown` or a `timeout` wrapper.
- **Session guard:** a new Claude Code Stop and StopFailure hook at the Solaris root. A registered project session
  that ends a turn with no clock armed is sent back with the start command (at most twice a turn); a fresh
  handover note or `--stop` marks a pause on purpose. Unarmed turn ends, safety-classifier stops and lasting API
  errors go to `<pack>/.memory/alerts.jsonl`.
- **Rules after a compaction:** for a registered session, the session-start hook loads the project's set (the
  commit and safety rules, `<pack>/card.md`, a block naming the project, its clock and the files to re-read, the
  pack's and plugins' rules) instead of the orchestrator's files.
- **The hard-rules card** `<pack>/card.md` (new, project-owned, at most about 3 KB): only the rules a session must
  hold after every compaction.
- **Housekeeping:** re-creatable data (a rule with `"recreatable": true` and a one-line `"how"`, or a
  `.recreatable` marker) is pruned without asking and logged with its how; submissions and raw traces are never
  deleted, raw data and run logs are protected by default (`protect_names`); `tidy` and `prune` hold what live jobs
  or running processes still use, and hold everything when the process list cannot be read.
- **Practice** (persona, subagents rule, handover skill, harness notes): a wake-up armed before every turn end;
  model text (agent prompts, model outputs, trajectories, long third-party text) kept out of the main session; the
  owner's recovery from a safety-classifier stop and a recheck after a fallback-model stretch; worker waits of at
  most about 270 seconds per call; explicit time limits on every command; answers after the last tool call.

## Moved Paths

None. New private files may appear in `<pack>/.memory/`: `clock.json`, `alerts.jsonl` (and, with resource-sharing
0.4.0, `host-health.json`, `host-health-state.json`); housekeeping keeps them in place.

## Migrate

1. `uv run -m solaris.tools.revs ff --dir <project>` (persona rev 51, subagents rule rev 10, handover rev 7, harness
   notes rev 7, model tiers rev 11, root `AGENTS.md` rev 25).
2. Update every copy-mode plugin whose source is newer (`uv run -m solaris.tools.version check-plugins --dir
   <project>`; `install-plugin`, update), following each plugin's own migrations (kaggle 0.10.0, resource-sharing
   0.4.0, reporting 0.4.2 in this release), then `uv run -m solaris.tools.plugins check --dir <project>`.
3. Write `<pack>/card.md` from `solaris/templates/ai-pack/ai/card.md` (placeholders filled) and fill it with the
   project's hard rules: what must never enter the main session, the wake-up, the confirm list, the few owner
   directions whose loss costs the most (keep their registry tags). At most about 3 KB.
4. A project that runs unattended: change its clock command to the new form (above) wherever the pack names it,
   and drop any `timeout`, `&` or hand cleanup of stray clocks. The next clock start registers the session.
5. Optional: name re-creatable data in `<pack>/housekeeping.json` (`"recreatable": true`, `"how"`), and set
   `protect_names` if the project's own rules must prune logs or raw data.
6. Record the plugin versions in `<pack>/manifest.json`, then `uv run -m solaris.tools.version set --dir <project>
   0.45.0`, `revs ff` and `revs baseline` again.
7. The project's own session, after the update: re-read the pack (persona, card, rules).

## Revert

`revs ff` is idempotent and the framework repo keeps the old masters in git: check out the 0.44.0 masters, re-run
`revs ff` and `revs baseline`, and `version set 0.44.0`. The card, `clock.json` and `alerts.jsonl` may stay (nothing
older reads them); `session_clock --forget` ends a session's project mode.
