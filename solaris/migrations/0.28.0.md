## Summary

0.28.0 gives every ai-pack a dedicated home for plugin shared files: overlays move from the pack root
(`ai/<name>/`, link files `ai/<name>.link.md`) into `ai/plugins/<name>/` / `ai/plugins/<name>.link.md`,
so pack-owned dirs (`ai/rules/`, `ai/skills/`, `ai/info/`) and plugin overlays no longer share a
namespace. The bundled `report` plugin is also renamed `reporting` (plugin 0.2.0 - its own
`plugins/reporting/migrations/0.2.0.md` covers the rename details). Risk is low: pure moves plus
reference fixes; nothing outside `ai/` changes except plugin-owned paths re-merged into the runtime MCP
config and project-owned references to moved files.

## Pre-flight checks

- [ ] `ai/manifest.json` exists, is valid JSON, and its `plugins[]` names match the dirs/link files
      present at the pack root (`ai/<name>/` for copies, `ai/<name>.link.md` for links).
- [ ] The working tree is clean enough to move files (no half-staged `ai/` changes).

## Migrate

1. Create `ai/plugins/` and move every copied plugin overlay: for each `{name, version}` entry in
   `ai/manifest.json` `plugins[]`, `git mv ai/<name> ai/plugins/<name>` - EXCEPT `report`, which moves
   straight to its new name: `git mv ai/report ai/plugins/reporting`.
2. Move every link-mode pointer: `git mv ai/<name>.link.md ai/plugins/<name>.link.md`. The path inside
   the file stays valid (it is relative to the ai-pack root, which did not move), but re-verify it
   resolves per `install-plugin` step 5.
3. In `ai/manifest.json` `plugins[]`, change `{"name": "report", ...}` to
   `{"name": "reporting", "version": "0.2.0"}` (other entries keep their names; bump `browserctl` /
   `visual-qa` to `0.2.1` if attached - patch releases, no plugin migration needed).
4. Re-key the revisions baseline for the moved files:
   `uv run -m solaris.tools.revs baseline --dir projects/<slug>`. The old baseline still keys plugin
   files under `ai/<name>/...`; without this re-key, classify sees the moved copies with no baseline
   and reports untouched files as `conflict`, so the next step cannot fast-forward them. Do this only
   after `update-project` step 1 has reconciled any merge-up/conflict verdicts - the re-key records the
   files' current state as the baseline, which erases an unresolved conflict signal.
5. `uv run -m solaris.tools.revs ff --dir projects/<slug>` - fast-forwards the moved copies to the
   current masters (template `AGENTS.md` rev 16 and `ai/engineer.agent.md` rev 36 name the new overlay
   home; plugin files whose content self-references overlay paths advance too, e.g.
   `reporting/report.skill.md` rev 4, `reporting/assets/style.css` rev 2, `browserctl.skill.md` rev 10,
   `visual-qa.skill.md` rev 11). `ff` updates the baseline for what it applies.
6. Re-merge each attached plugin's `mcps.json` into the project runtime MCP (`.mcp.json` +
   `.cursor/mcp.json`) so server command paths point into `ai/plugins/` (e.g. the `visual-qa` server now
   runs `ai/plugins/visual-qa/eyes.py`); verify with `uv run -m solaris.tools.mcp_sync --check`.
7. Fix project-owned references to the old paths: grep the project for `ai/<each plugin name>/` and
   update hits in project-authored files (`ai/engineer.instructions.md`, workspace docs, report HTML
   sources' stylesheet links per `plugins/reporting/migrations/0.2.0.md`, `reports/theme.css` comments).
   Leave `ai/.memory/` history files (logs, context) as-is.
8. Rebuild the baseline once more: `uv run -m solaris.tools.revs baseline --dir projects/<slug>`
   (idempotent; guarantees every `revisions` key is an `ai/plugins/...` path).

## Validate

- [ ] `uv run -m solaris.tools.revs classify --dir projects/<slug>` reports every file in-sync.
- [ ] No overlay dirs or `.link.md` files remain at the pack root: the only dirs under `ai/` are
      `rules/`, `skills/`, `info/`, `plugins/`, `.memory/` (plus pack files).
- [ ] `uv run -m solaris.tools.version check-plugins --dir projects/<slug>` reports every plugin `ok`
      (and `reporting`, not `report`).
- [ ] `uv run -m solaris.tools.mcp_sync --check --dir projects/<slug>` passes; any plugin-provided MCP
      server command resolves under `ai/plugins/`.

## Revert

1. Move the overlays back (`git mv ai/plugins/<name> ai/<name>`; `reporting` back to `ai/report`), move
   link files back to `ai/<name>.link.md`, restore from git history the previous `ai/manifest.json`
   plugins entries AND the fast-forwarded files step 5 advanced (`AGENTS.md` rev 15,
   `ai/engineer.agent.md` rev 35, the plugin files at their prior revs - they now name the new overlay
   home and would mislead a reverted pack), undo the step 7 reference edits, re-merge the previous
   plugin `mcps.json` paths, and re-run `uv run -m solaris.tools.revs baseline --dir projects/<slug>`.
