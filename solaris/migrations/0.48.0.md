## Summary

Framework 0.48.0 makes autocode the only compaction in a project that runs under it, and keeps its sessions working
after a compaction. Below, `<pack>/` is the project's ai-pack folder and `<project>` its path from the Solaris root.

- **Self-compaction off with the autocode plugin:** `session_compact` treats a pack with the `autocode` plugin
  attached (in its manifest's `plugins`, or linked through `<pack>/plugins/autocode.link.md`) as
  `selfcompact.enabled` false. Only the project's own `<pack>/.memory/config.json` or `<pack>/defaults.json` turns it
  back on (the framework's `.memory/config.json` does not); `check` names the reason.
- **autocode plugin 0.2.0** (rule rev 3): a project session no longer needs `session_compact set-limit off` at start
  (a session outside a project still runs it), and `[autocode] compaction done` (autocode 1.0.0-rc4 and later) is
  the cue to reload the read-first set and carry on with the steps `context.md` lists, without waiting to be asked.
- Projects without the autocode plugin: nothing changes.

## Moved Paths

None.

## Pre-flight Checks

- [ ] `<pack>/manifest.json` exists and is valid JSON.
- [ ] With the autocode plugin attached: its autocode server runs 1.0.0-rc4 or later for `compaction done` (older
      servers still compact; the session then waits for its next wake after a compaction).

## Migrate

1. `uv run -m solaris.tools.version set --dir <project> 0.48.0`, then `uv run -m solaris.tools.revs ff --dir
   <project>` and `uv run -m solaris.tools.revs baseline --dir <project>`.
2. With the autocode plugin copied into `<pack>/plugins/autocode/`: update the copy (`install-plugin`, "update plugin
   autocode in `<project>`"), so its rule is rev 3 and the manifest records `0.2.0`. A linked plugin needs nothing.
3. A running autocode session re-reads `<pack>/plugins/autocode/autocode.rule.md` at its next start or compaction;
   tell it to now if it should act on the change at once.

## Validate

- [ ] `uv run -m solaris.tools.version check --dir <project>` exits 0.
- [ ] With the autocode plugin attached: `uv run -m solaris.tools.session_compact check --dir <project>` reports
      `enabled: false` (unless the project's own config turns it on).

## Revert

Check out the 0.47.0 masters, re-run `revs ff` and `revs baseline`, and `version set 0.47.0`; copy the autocode
plugin 0.1.0 back if it was updated. A session that should not self-compact then runs `session_compact set-limit off`
at start again, as rule rev 2 says.
