## Summary

Framework 0.27.0 ships a **git collaboration workflow in every ai-pack**: developers work on
personal `<id>-develop` branches (auto-switch before any commit on `main`/`develop`), commits on
personal/feature branches are automatic per the commit policy, pushes are never automatic, and
back-contribution happens only on an explicit ask as a PR against `main`. Feature requests branch
`feature-<descr>` and merge-commit back when done. Two pack switches control it:
`"git.developer_branches"` (off = main-developer mode, `main` is fine) and
`"git.feature_branches"`, both on by default and overridable per machine in
`ai/.memory/config.json`. The init stub also gains a skip-any-resource option (e.g. proceed
GPU-host-less to explore). No ai-pack schema change.

## Migrate

1. Sync the templates: `uv run -m solaris.tools.revs ff --dir <project>` - brings
   `ai/rules/git-collab.rule.md` (rev 2) and fast-forwards `ai/engineer.agent.md` to rev 35,
   `ai/skills/init.skill.md` to rev 6, `ai/skills/refresh.skill.md` to rev 8. Resolve any
   `merge-up`/`conflict` per `update-project`.
2. Add the switch keys to the committed defaults (`ai/defaults.json` is seeded per project, not
   rev-synced): JSON-merge `"git.developer_branches": true` and `"git.feature_branches": true`,
   **add-if-absent only** - never overwrite a project's existing values.
3. Project owners who work directly on `main`: set `"git.developer_branches": false` in the
   private `ai/.memory/config.json` (create the file if needed) - machine-local, never committed.
4. Re-record the baseline: `uv run -m solaris.tools.revs baseline --dir <project>`.
5. `uv run -m solaris.tools.version set --dir <project> 0.27.0`.
